## 3. 核心使用逻辑

系统现在围绕一句话工作：

> 每个对客户、门店、经销商、品牌方、媒体、艺人或公司内部的承诺，都必须有唯一当前负责人、明确截止时间、下一步动作和可见的等待对象。

推荐的日常顺序为：

1. 员工从首页行动中心进入“今天、逾期、等待外部、待确认”的工作。
2. 新工作使用 Hotone 模板创建，并补齐业务类型、当前负责人、截止日和下一步动作。
3. 工作交接时直接替换唯一当前负责人，不再把多人 assignee 当成共同负责。
4. 外部等待时记录等待对象和等待开始时间；完成或恢复推进时清理等待状态。
5. 管理者从运营报表查看逾期、长期等待、无人负责和即将到期项目，并下钻到具体工作项。
6. Pages 用于 Brief、会议记录、流程说明和复盘；库存、订单、客户资料、完整 RMA 等仍留在各自真值系统。

## 4. 已完成的功能与缺陷修复

### 4.1 数据完整性与任务层级

- 统一校验父子任务关系，禁止跨工作区、跨项目、引用自身和形成循环层级。
- 删除、归档、恢复父任务时同步处理后代，避免遗留孤儿任务或状态不一致。
- 修复多个入口对父子关系处理不一致的问题，并补充 API、应用层和后台任务回归测试。
- 修复用户偏好跨工作区串用的问题。

### 4.2 唯一当前负责人和运营字段

- 增加并贯通业务类型、当前负责人、等待对象、等待开始时间和下一步动作。
- 当前负责人改为单值操作：选择新负责人即替换，清空即无人负责；Power-K 快捷命令遵循同一规则。
- 修复显式选择“无人负责”后又被项目默认负责人覆盖的问题。
- 修复 PATCH 返回旧数据导致等待时间不能立即刷新的问题。
- 更新时锁定并刷新任务，避免两名同事同时修改不同字段时互相覆盖。
- 数据迁移 `0125_single_current_issue_owner` 会先归并历史重复负责人，再建立数据库级唯一约束。

### 4.3 Hotone 工作流、首页和管理报表

- 增加 Hotone 工作流一键安装入口与幂等 API，适配新品上市、内容、渠道、活动和售后升级等内部工作。
- 首页加入运营行动中心，并根据权限正确禁用创建按钮和说明原因。
- 增加可下钻的运营报表，聚焦逾期、等待、无人负责、即将到期等行动指标。
- “全部工作”收敛为四个系统视图并固定列表布局，减少个人视图和复杂布局造成的理解差异。
- 增加全局归档快捷操作，统一任务详情、列表、预览和快捷命令中的行为。

### 4.4 Pages、Inbox、通知和导出

- 修复 Pages 空标题、创建/删除/导出反馈、离线提示和版本信息等桌面流程问题。
- 补充适合内部使用的页面模板与模板选择器。
- 修复 Inbox 中字段展示和创建逻辑不一致的问题。
- 修复切换工作区或通知分类后仍保留旧通知选中状态的问题，并在 store 层再次校验选择有效性。
- 导出限制为管理员能力，并修复过滤条件没有正确作用于导出结果的问题。

### 4.5 成员角色和防误操作

- Workspace 与 Project 角色修改只接受单一 `role` 字段；生命周期字段和额外字段返回 400。
- 普通项目成员不能修改他人角色。
- 离开、删除或降级前保护最后一名 Workspace 管理员和 Project 管理员。
- Workspace 降级会在验证成功后正确同步项目角色。
- 角色修改、删除和离开采用一致的数据库锁顺序，并在持锁后重新校验权限。
- 新增并发降级测试，防止两次同时操作把项目变成零管理员。
- 最终独立复核结果：P0 = 0、P1 = 0、P2 = 0。

### 4.6 功能精简

针对十人左右的内部团队，已移除或隐藏以下干扰项，并增加直接访问旧 URL 时的保护：

- 商业订阅、升级销售和外部支持入口。
- 不使用的第三方集成入口与相关前端服务。
- 公开发布项目等不符合内部边界的能力。
- 自动化和估算入口。
- 自定义 Views、Spreadsheet、Gantt 等重型布局。
- Cycles、Intake 等敏捷流程入口；Modules 仅保留为可控试点，而不是默认主流程。

原则是减少导航和决策成本，而不是简单删除底层通用能力。旧收藏或直接链接不会再把用户带进一个半可用页面。

### 4.7 桌面 UI/UX、品牌和语言

- 登录、错误、维护、邀请、首页、侧栏、管理端和邮件统一为 Hotone Japan 内部系统语境。
- 使用现有 Hotone logo 资源替换关键 Plane 品牌露出；本阶段没有为了装饰额外生成图片。
- 补齐关键桌面流程的日语、简体中文和英语文案，并增加自动完整性检查。
- 修复多个无标题按钮、可访问名称、错误重试、空状态和操作反馈问题。
- God Mode 统一在 `/god-mode` 运行，并验证深链接与静态资源 MIME/路径。

## 5. 保留与不建议继续扩展的功能

### 应保留

- 项目、工作项、子任务、状态、优先级、标签、截止时间。
- 唯一当前负责人、等待对象、下一步动作和业务类型。
- 评论、附件、活动记录、Pages、通知、搜索、归档和受控导出。
- 首页行动中心、运营报表、Hotone 模板和轻量 Modules 试点。
- Workspace/Project 管理与 God Mode。

### 暂不建议增加

- CRM、库存、采购、会计、完整 RMA、文件库。
- 工时计费、故事点、燃尽图和复杂 Sprint 管理。
- 更多仪表盘图表、更多自定义视图、自动化市场或插件市场。
- 面向外部客户的注册、社区、公开项目和商业订阅流程。

这些记录可以通过链接或摘要关联，不应在 HTJPplane 中复制另一套真值数据。

1. 在远端 CI 中运行包含 PostgreSQL/Redis、迁移、`makemigrations --check`、迁移回归和目标 API 测试的完整流程。

如果其中任一步失败，应停止上线并修复，不应绕过迁移或测试门禁。
